# Скрипты

Нужен Python 3.9+ и Pillow (`pip install pillow`). Запуск из корня репозитория, одной командой:

```
python scripts/run.py all        # разложить -> привести размер -> проверить комплектность
python scripts/run.py organize   # только раскладка
python scripts/run.py convert    # только размер и формат
python scripts/run.py check      # только проверка
```

Каждый скрипт запускается и отдельно (`python scripts/check.py`). `--help` покажет все ключи.
Код возврата 0 — всё в порядке, 1 — есть замечания. По нему видно результат в CI или в `&&`.

## Что делает каждый

| Скрипт | Что делает | Ключи |
|---|---|---|
| `organize.py` | Берёт файлы из `Входящие/`, по имени определяет артикул (или модель) и номер кадра, переименовывает и раскладывает: карточки → `export/ready/<Артикул>/<Артикул>_<N>.png` (с `_draft` — в `export/draft/<Артикул>/`), фото моделей → `Генерация/Кадры/<Модель>_<N>.jpg`. Терпит регистр, пробелы вместо `_`, `@2x`. Неопознанное остаётся во «Входящих» | `--dry-run`, `--force` |
| `convert.py` | Карточки → PNG 1080 × 1440 sRGB без прозрачности и метаданных, до 10 МБ (экспорт 2× сжимается). Фото → JPG 1536 × 2752, качество 95. Пропорции не искажаются: неподходящий кадр — ошибка, а не растяжка. Фото меньше нужного размера пропускаются (апскейл деталей не добавляет). Оригиналы уходят в `Входящие/_исходники/` (в .gitignore) | `--dry-run`, `--upscale` |
| `check.py` | По `Данные.csv` проверяет для каждого артикула 4 карточки (размер, формат, `_draft` там, где в данных `?????`), для каждой модели фото кадров 1, 2, 4, и наличие `Фото/<Артикул>.jpg`. Ловит лишние файлы, русские буквы и пробелы в именах, файлы не на своём месте, вес больше 10 МБ | `--articles ...`, `--no-photos` |

## Требования площадок

Выгрузка рассчитана на Wildberries и Ozon: PNG 1080 × 1440 (3:4, выше рекомендованных 900 × 1200
и минимумов 700 × 900 у WB и 200 × 200 у Ozon), sRGB, до 10 МБ на файл. Цифры взяты из обзоров
для продавцов; перед первой загрузкой сверьте их в справке площадок. Лимит веса лежит в
`MAX_UPLOAD_BYTES` (`scripts/common.py`).

## Петля генерации

`loop.py` — журнал и предохранитель петли «сгенерировали → проверили → поправили запрос → повторили»
(сама петля описана в навыке `.claude/skills/generation-loop`, запускается в Claude Code как
`/generation-loop AVT-CR 1`). Скрипт держит три правила: не больше 3 кругов, запрос повторного круга
должен отличаться от прошлого и сопровождаться пояснением `--change`, каждый круг пишется в
`Генерация/Журнал генераций.md`. После третьего брака (или замечания, которое запросом не лечится,
например размер файла) печатает остановку с диагнозом: проблема в задании или данных. Код возврата:
0 годен, 10 повторить, 20 стоп.

## Типичный сценарий

1. Экспортировали кадры из Figma или скачали фото из генератора, положили во `Входящие/`.
2. `python scripts/run.py all`.
3. Если в отчёте есть «ОШИБКА» или «ПРОПУСК», кадр надо переэкспортировать или перегенерировать.
   Подробности по каждому в самом отчёте.

Правила (размеры, имена, `_draft`) взяты из `Критерии кадра.md` и `Генерация/Генерация фото.md`;
все константы лежат в одном месте, `scripts/common.py`.
